项目地址：[bestcf.pages.dev](https://bestcf.pages.dev/)

如果你已经跟着 `edgetunnel` 之类的项目在 Cloudflare 上部署过 VLESS 节点，大概率会遇到下一个问题：**节点能连上，但速度不理想；想找教程优化，却发现信息散落在几十个仓库、博客和群聊记录里。** `bestcf.pages.dev` 解决的不是“怎么部署”，而是“部署完之后，那些你迟早要用到的东西该去哪里找”。

## 它本质上是一个 EDT 资源导航站

打开 `bestcf.pages.dev`，你会看到一个名为“CF EDT 导航 / EDT AIO NAV”的页面。它不提供代理服务，也不托管任何节点，做的事情是把 Cloudflare EDT（Edge Tunnel）生态里分散的资源**收拢到一个页面上**。

这个定位听起来简单，但在当前的信息环境下有实际意义。围绕 Cloudflare 免费代理的脚本、教程和优选资源更新频率很高，一个链接失效、一个 IP 段被标记，都会直接影响使用体验。把入口集中在一处，至少能减少“到处翻找最新可用资源”的时间成本。

## 它聚合的三类核心资源

页面内容大致可以分成三个板块，恰好对应了从部署到优化的完整链条。

**第一类是 EDT 脚本库。** 页面列出了这个生态里几个有代表性的项目，并用一句话标注了各自的定位：`zizifn/edgetunnel` 是“鼻祖”，`6Kmfi6HP/EDtunnel` 做了深度重构，`YGKKK` 以手把手教程普及了 EDT，`BPB` 第一个把配置做成了可视化面板，`cmliu/edgetunnel` 则被描述为“一站式体验推荐”。对于刚接触这个领域的人来说，这份清单本身就是一张**项目选型地图**，不需要逐个打开 GitHub 仓库读 README 才能判断哪个适合自己。

**第二类是教程链接。** 页面收录了视频和文字两种形式的教程，覆盖从零搭建、Clash/mihomo 配置到 DoH 自建等不同环节。文字版教程尤其适合需要反复对照操作步骤的场景，比在视频里拖进度条要高效得多。

**第三类是优选域名与优选 IP 资源，这也是整个页面最有实用价值的部分。** 页面按来源和更新频率整理了大量 `txt` 格式的订阅链接，包括 WeTest、UOUIN、LuoLi、CM（cmliu）、天诚、MJZ 等多个优选源，并标注了更新周期（每半小时、每小时、早中晚等）和覆盖的运营商或地区。对于在 `edgetunnel` 面板或环境变量里配置订阅的用户来说，这些链接可以直接填入使用，省去了自己扫描 IP、测速、筛选的步骤。

## 为什么值得单独写一篇文章推荐

`bestcf.pages.dev` 的价值不在于技术上的原创性，而在于它做了一件在中文 EDT 社区里很少有人系统去做的事：**维护一份可持续更新的资源入口**。

Cloudflare 的优选 IP 时效性很强，一个今天测速优秀的 IP 明天可能就变慢或被标记。单个博客文章的推荐往往在发布几周后就过时，而一个持续更新的导航页可以在一定程度上缓解这个问题。页面本身标注了各个优选源的更新频率，用户至少能判断手里的链接是否还在“活跃期”。

另外，它把“脚本选型”和“优化资源”放在同一个页面下，形成了一条自然的路径：先确定用哪个脚本部署，再用页面里提供的优选资源去调优。这种**上下文连贯性**，是零散收藏多个链接很难替代的。

## 适合谁用，不适合谁

这个页面最适合**已经决定使用 Cloudflare EDT 方案、正在进入优化阶段的人**。如果你还在犹豫要不要用 Worker/Pages 跑代理，页面里的脚本对比和教程链接也能帮你快速建立整体认知。

但它不适合指望“打开就能翻墙”的用户。`bestcf.pages.dev` 本身不提供任何可直接连接的节点或订阅，它只是一组指向其他资源的链接集合。真正要使用，你仍然需要自己部署一个 Worker/Pages 项目，或者从页面里找到教程完成搭建。

另一个需要留意的现实是：Cloudflare 对这类用法的态度始终没有明确背书，优选 IP 的可用性也会随网络环境和平台策略变化。页面里聚合的链接越多，失效的概率也越分散——某个源停止更新或某个 IP 段被调整，都是这个生态里正常会发生的事。把它当作一个**降低信息搜寻成本的起点**，而不是一劳永逸的答案，预期会更合理。

## 小结

如果你已经在用或打算用 `edgetunnel` 这类项目，`bestcf.pages.dev` 值得放进浏览器书签栏。它不会替你完成部署，也不会保证每个链接永远可用，但它把 EDT 生态里最耗时的“找资源”这一步，压缩到了一个页面里。对于这个更新频繁、信息高度分散的领域来说，这件事本身就比多数教程更有持续价值。
